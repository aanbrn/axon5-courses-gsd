---
description: Install or verify GSD Core, check the required tools, and optionally connect the user-level MCP servers
---

Run `./scripts/setup-tooling.sh` with the shell tool and report its output verbatim.

Arguments:

- no argument — install or verify the pinned GSD Core, then report the prerequisites;
- `--force` — reinstall the pinned version even when it matches;
- `--check` — install nothing, verify the prerequisites, exit non-zero when a tool is missing;
- `--mcp` — after the script's report, load the `connect-mcp-servers` skill and follow it. Never pass
  `--mcp` to the script: it is this command's flag, and the script rejects it.

When `--mcp` is present:

1. Run the script with any remaining flags, and report its output.
2. Load the skill `connect-mcp-servers` and carry out its procedure: detect the environment, install
   what is missing, wire the user's global config, verify the result, and hand back only the steps a
   human must perform.
3. A non-zero exit from the script does not skip step 2 — report the failure and still finish the MCP
   wiring.
4. Without `--mcp`, never touch `~/.config/opencode/opencode.jsonc`: a plain run must leave the user's
   machine as it found it.

Context for the script run:

- The script is idempotent: it compares `.opencode/gsd-core/VERSION` with the pinned `1.20.1` and installs only when they differ.
- It installs GSD Core for OpenCode at project scope (`--opencode --local`) and then verifies that `gsd-tools` can read `.planning/config.json`.
- Use `--check` when the question is "can this machine build the project?", not "install GSD".
- Do not edit any other file, and do not hand-edit `.opencode/opencode.json` — it is generated by the installer.

If the script fails, report the exact error and the failing step; do not attempt a different install method.
